
### 16.57 磨砂玻璃 v1.3.0：五项观感修正（背景审美 / 折射归一 / 下拉刷新 / 玻璃厚度 / 齿轮图标）（2026-11-10）

#### 16.57.1 需求来源

§16.55/§16.56 交付的透射玻璃方向被认可，但观感有 5 处不达预期。用户原话
（逐条对应下文修复项）：

> 第一，为什么界面背景改成这样了，虽然这样不错，但是我希望你再提高一下审美，
> 这个方向可以，就是希望审美再好一点，第二logo和搜索框的透射和下面的dock栏
> 不一样好像是折射的，第三下拉刷新的那个progress组件动画你现在是做到从顶部
> 出现也就是logo栏的上面出现的这不对，应该是下方出现，而且首页刷新没有效果，
> 第三，透射玻璃不要做透明，要做稍微模糊，也不要做很模糊，懂吧，这个参考vivo
> 的组件设计，第四我的界面的右上角的设置的svg不对，应该使用传统的设置的图标

#### 16.57.2 五项修复与根因

**① 背景审美：深色相 + 低 alpha 出不了色，必须浅色相 + 中等 alpha**

第一版把 `Palette.BrandSecondary`（#312C85 深靛）以 alpha 0.16 铺底，期望「淡紫」。
截屏取色实测：`(12,300) = rgb(219,218,219)`、`(12,1200) = rgb(212,213,212)` ——
全是中性灰，屏幕上看不出任何色相。**深色相混白不是「淡色」而是「灰」**。

改为浅色相 + 中等 alpha（`ui/components/GlassPageBackdrop.kt` 的 `PageGlow`）：
`primary = Color(0xFFB9AEFF)` 淡紫 0.50 / `accent = Color(0xFFFFCBA8)` 杏 0.42 /
`tertiary = Color(0xFF9FE3DA)` 薄荷 0.34 / `quaternary = Color(0xFFFFB3C8)` 樱粉 0.30。
实测 `(12,300) = rgb(224,220,231)` 淡紫、`(1068,300) = rgb(235,222,223)` 淡粉，色相可辨。

同时把四团径向渐变的半径从 0.70~0.86×maxDim 拉到 **1.00~1.15×maxDim**：半径小于屏宽时
渐变边界落在屏内，四团各有一圈可辨的「边」，叠成四块圆形色斑；拉到超过屏宽后
边界出画，才是「柔光」。另加底部 `Transparent → bottomShade` 垂直渐变（0.62h → h）
压住 Dock 区域的亮底。

把 `PageGlow` 与 `rememberPageGlow()` 提成私有类 + 组合函数，供 `glassPageBackdrop()`
与 `GlassPage()` 共用——此前两处内联各算一份 alpha，改一处忘另一处的风险已经出现过。

**② 顶栏/搜索框「像折射」、Dock 不像：折射深度是绝对值，没按控件尺寸归一**

`GlassSurface` 所有实例走同一个 `glassRenderEffect`，参数只有 `blurPx` / `refractPx` /
尺寸。AGSL 里 `float2 d = xy / c - 1.0`（`c = uSize * 0.5`）是**归一化到控件自身**的坐标，
而 `uRefract` 是绝对像素。44dp 顶栏/搜索框半高 22dp，3dp 占 13.6%，整个面都在弯；
56dp Dock 占 10.7%。短控件弯得过头 → 观感是「一块会扭的塑料」。

修法（`ui/components/GlassSurface.kt`）：
```kotlin
private const val GLASS_REFRACT_RATIO = 0.05f   // 短边 5%
private const val GLASS_REFRACT_MAX_DP = 3      // 上限，长边控件不弯过头
val refractPx = (minOf(size.width, size.height) * GLASS_REFRACT_RATIO)
    .coerceIn(1.5f * density, GLASS_REFRACT_MAX_DP * density)
```
并把 AGSL 的 `smoothstep(0.4, 1.0, r)` 抬到 `smoothstep(0.66, 1.0, r)`：中间 2/3 完全不动，
只有贴边一薄圈外推。`GLASS_SATURATION` 1.6f → 1.28f（磨砂只柔化不改色相浓度，
1.6 在浅色柔光底上泛塑料品红）。

**③ 下拉刷新：indicator 位置错 + 首页刷新无反馈**

位置：`PullToRefreshBox` 的 `indicator` 是 `BoxScope` 插槽（Material3 1.9.0
`PullToRefresh.kt:120`），默认 `Indicator(modifier = Modifier.align(Alignment.TopCenter))`
且 `translationY` 从 `-size.height` 起算，于是画在顶栏玻璃之上。新增
`ui/components/GlassPullIndicator.kt`（`@Composable fun GlassPullIndicator(state, isRefreshing, modifier)`）：
36dp 圆环 + 18dp `CircularProgressIndicator`，`alpha = if (isRefreshing) 1f else 0.45f + fraction * 0.55f`、
`scale = if (isRefreshing) 1f else 0.82f + fraction * 0.18f`，不可见时直接 return（透明圆环会吃点击）。
首页 `padding(top = topPad + 8.dp)`、分类页 `padding(top = topPadding + 52.dp)` 避开 44dp 分段控件。

「没效果」有两个真因：
1. `RecommendPage` 原判断 `cs.errMsg != null` —— `errMsg` 是**非空 String**，条件恒 true，
   于是版块为空且无错误时也走 `ErrorView(message = "")` → 屏幕一片空白。改为
   `cs.sections.isEmpty() && cs.errMsg.isNotEmpty()`。
2. 刷新成功没有任何反馈，而源站常返回同一批内容。新增 `CatState.notice: String`（与
   `errMsg` 分开：不是错误），`refreshRecommend` 成功分支写
   `"已刷新 · N 个内容"`（N = 各版块条目数之和）；新增 `dismissNotice(idx)`；
   `RecommendPage` 用 `LaunchedEffect(notice) { delay(2600); onNoticeShown() }` 自动消失。

反馈条**必须是浮层**：第一版作为 `LazyColumn` 的 `item`，被 `contentPadding.top`
顶到玻璃顶栏背后，实测只能看到半截「已刷新」。改为
`Box { LazyColumn(...); if (notice.isNotEmpty()) InlineNotice(Modifier.align(TopCenter).padding(top = topPadding + 8.dp)) }`。

**④ 玻璃厚度：从「透射」改回「磨砂」，参考 vivo OriginOS**

v4 为追求「透」把 `fill` 压到 42% 白、`liquidTint` 9%，结果像塑料膜。磨砂的正解是
**白面够实 + 模糊够浅**（`ui/theme/Glass.kt`）：

| token | v4 | v1.3.0 | 理由 |
|---|---|---|---|
| `LightGlass.fill` | `0x6BFFFFFF` 42% | `0x99FFFFFF` 60% | <45% 像塑料膜，>75% 变回白卡 |
| `LightGlass.liquidTint` | `0x17FFFFFF` 9% | `0x66FFFFFF` 40% | 24% 时海报上的字仍可读；40% 是「能看出有图、读不清字」的分界 |
| `LightGlass.chipFill` | `0x3DFFFFFF` | `0x5CFFFFFF` | 跟随主面 |
| `DarkGlass.fill` | `0x2EFFFFFF` 18% | `0x1CFFFFFF` 11% | 见下「深色对比度」 |
| `DarkGlass.liquidTint` | `0x29FFFFFF` | `0x1CFFFFFF` | 同上 |
| `GLASS_BLUR_RADIUS_DP` | 9dp | **16dp** | 9dp 能看清海报上的字（太薄）；>20dp 糊成均匀色雾 |

**深色主题的连带缺陷（本轮一并修）**：深色卡片实测 `rgb(140,137,154)`，而
`DarkPalette.textSecondary` 是 `0xFF9B9B93` = `rgb(155,155,147)` —— 两者几乎同亮度，
「登录两个BT 解锁 4K 高清线路」直接糊在卡片里。两处根因：

1. `GlassSurface` 的静态高光 `sheen` 硬编码
   `if (fill.luminance() < 0.5f) 0.10f else 0.34f`，判据是 fill 的**算术亮度**。深色主题的
   fill 是低 alpha 白（`0x1CFFFFFF`，luminance≈0.11），被判成「暗色」走 0.10f 分支，
   但叠在深色柔光底上仍把卡片整体抬亮一档。高光强度是**主题属性**不是 fill 属性，
   提升为 `GlassScheme.sheenAlpha` token（`LightGlass = 0.30f` / `DarkGlass = 0.06f`）。
2. `DarkPalette.textSecondary` `0xFF9B9B93` → `0xFFB6B6AD`：在 `rgb(95,91,114)` 的玻璃卡上
   对比度从约 2.5:1 提到约 4.4:1。

修复后实测：卡片 `rgb(95,91,114)`、副文本 `rgb(143,141,147)`，拉开一档且可读。

**⑤ 设置图标：手写折线齿轮 → Material Icons 官方 pathData**

原 `DyIcons.Settings` 是 24 段手写折线近似，齿形不对称，缩到 20dp 像不规则花形。
替换为 Material Icons `settings` 官方 24×24 pathData 逐段转出的 `Path`
（`moveTo(19.43f, 12.98f)` 起 12 齿外圈 + `moveTo(12f, 15.5f)` 内圈孔，
全 `cubicTo` 绝对坐标，`fillType = PathFillType.EvenOdd`）。
转换用 Node 脚本（`python`/`python3` 在本机是 WindowsApps stub，`py -3` 报
`No suitable Python runtime found`，Git Bash heredoc 写 Python 也不稳）。

#### 16.57.6 未验证 / 边界

- 只验 1080×2400 / 420dpi 一档；未验折叠屏、平板、横屏。
- 真机（vivo V2419A / Android 17）安装被系统拦下
  （`INSTALL_FAILED_ABORTED: User rejected permissions`），需人工在手机上点允许，本轮未完成真机复验。
- API < 33 的 `BlurEffect` 退化路径（无 AGSL 折射）仍未在任何设备实测。
- 「首页刷新」的可见变化依赖源站返回新内容；notice 只解决「有没有反应」的感知，
  不解决「内容是否真的换了」。
- 滚动帧率仍未做 `gfxinfo` 基线对比；`GlassPage` 每帧一次 `drawPageGlow` + 每玻璃件一次
  `renderEffect` 链，低端机可能掉帧。
